## Overview

This document outlines the comprehensive testing strategy for the AICN Training Management System API. The test suite covers all modules including authentication, sessions, enrolments, certificates, trainers, and admin functionalities.

### Testing Stack
- **Jest** - Test runner and assertion library
- **Supertest** - HTTP assertion library for API testing
- **PostgreSQL** - Test database
- **Prisma** - Database ORM for test data management

### Test Principles
- **Isolation** - Each test runs in isolation with clean database state
- **Repeatability** - Tests produce same results regardless of execution order
- **Comprehensiveness** - Cover happy paths, edge cases, and error scenarios
- **Speed** - Optimized for fast execution with proper setup/teardown

```javascript
describe('Authentication Module', () => {
  describe('POST /api/auth/signup', () => {
    it('should register a new user with valid data', async () => {
      const res = await request(app)
        .post('/api/auth/signup')
        .send({
          name: 'John Doe',
          email: 'john@example.com',
          password: 'Test@123456',
          phone: '+254712345678',
          county: 'Nairobi'
        });
      
      expect(res.status).toBe(201);
      expect(res.body.success).toBe(true);
      expect(res.body.data.user).toHaveProperty('id');
    });

    it('should reject registration with invalid email format', async () => {
      const res = await request(app)
        .post('/api/auth/signup')
        .send({
          name: 'John Doe',
          email: 'invalid-email',
          password: 'Test@123456'
        });
      
      expect(res.status).toBe(400);
      expect(res.body.errors).toEqual(
        expect.arrayContaining([
          expect.objectContaining({ field: 'email' })
        ])
      );
    });
  });
});
```

## Best Practices

### Test Naming Convention
```javascript
// Good
it('should register a new user with valid data', async () => {})
it('should reject registration with duplicate email', async () => {})

// Bad
it('test signup', async () => {})
it('works', async () => {})
```

### Test Organization
```javascript
describe('Module Name', () => {
  describe('GET /api/endpoint', () => {
    beforeEach(() => {})
    afterEach(() => {})
    it('should ...', async () => {})
  })
  
  describe('POST /api/endpoint', () => {
    it('should ...', async () => {})
  })
})
```

### Assertions
```javascript
// Use specific assertions
expect(res.status).toBe(200)
expect(res.body).toHaveProperty('data')
expect(res.body.errors).toEqual(
  expect.arrayContaining([
    expect.objectContaining({ field: 'email' })
  ])
)

// Avoid generic assertions
expect(res.body).toBeDefined() // Too vague
```

### Cleanup
```javascript
afterEach(async () => {
  await cleanDatabase() // Reset database state
})

afterAll(async () => {
  await prisma.$disconnect() // Close connections
})
```

## Troubleshooting

### Common Issues

| Issue | Solution |
|-------|----------|
| Database connection refused | Ensure PostgreSQL is running and DATABASE_URL is correct |
| Tests timing out | Increase testTimeout in jest.config.js |
| Port already in use | Change PORT in .env.test |
| Migration errors | Run `npx prisma migrate reset --force` |
| Token validation fails | Ensure JWT_SECRET matches in test environment |

### Debugging Tests

```bash
# Run single test with debug output
npx jest --verbose --runInBand tests/auth/auth.test.js

# Run with node inspector
node --inspect-brk node_modules/.bin/jest --runInBand

# Show console.log output
npx jest --verbose --testNamePattern="should register"

# Run without cache
npx jest --no-cache
```

### GitHub Actions Workflow (`.github/workflows/test.yml`)

```yaml
name: API Tests

on:
  push:

env:
  NODE_VERSION: '18.x'
  DATABASE_URL: postgresql://postgres:postgres@localhost:5432/aicn_test
  JWT_SECRET: test-jwt-secret

jobs:
  test:
    runs-on: ubuntu-latest
    
    services:
      postgres:
        image: postgres:14
        env:
          POSTGRES_USER: postgres
          POSTGRES_PASSWORD: postgres
          POSTGRES_DB: aicn_test
        ports:
          - 5432:5432
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5

    steps:
      - uses: actions/checkout@v3
      
      - name: Use Node.js ${{ env.NODE_VERSION }}
        uses: actions/setup-node@v3
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'npm'
      
      - name: Install dependencies
        run: npm ci
      
      - name: Run database migrations
        run: npx prisma migrate deploy
        env:
          DATABASE_URL: ${{ env.DATABASE_URL }}
      
      - name: Run tests
        run: npm test
        env:
          NODE_ENV: test
          DATABASE_URL: ${{ env.DATABASE_URL }}
          JWT_SECRET: ${{ env.JWT_SECRET }}
      
      - name: Upload coverage to Codecov

          file: ./coverage/lcov.info
```

## Troubleshooting

### Common Issues and Solutions

| Issue | Solution |
|-------|----------|
| **Database connection refused** | Ensure PostgreSQL is running and test database exists |
| **JWT secret not set** | Set JWT_SECRET in .env.test |
| **Port already in use** | Change PORT in .env.test or kill process on port |
| **Migration errors** | Run `npx prisma migrate reset --force` |
| **Tests timing out** | Increase testTimeout in jest config |
| **Concurrent test conflicts** | Use `--runInBand` flag for sequential execution |

## Best Practices

### Writing Tests

1. **Arrange-Act-Assert pattern**
```javascript
it('should create enrolment', async () => {
  // Arrange
  const session = await createTestSession();
  
  // Act
  const res = await request(app)
    .post('/api/enrolments')
    .set('Authorization', `Bearer ${token}`)
    .send({ sessionId: session.id });
  
  // Assert
  expect(res.status).toBe(201);
  expect(res.body.success).toBe(true);
});
```

2. **Isolate tests** - Each test should be independent
3. **Use descriptive test names** - Should explain expected behavior
4. **Test both success and failure cases**
5. **Mock external services** (email, notifications)
6. **Clean up test data** after each test suite

### Test Naming Convention

```javascript
// ✅ Good
it('should return 400 when email format is invalid', () => {...})
it('should create session when user is admin', () => {...})

// ❌ Bad
it('test validation', () => {...})
it('works', () => {...})
```
