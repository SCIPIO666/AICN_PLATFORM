## Authentication Setup

### Step 1: Open Swagger UI
```
http://localhost:3000/api-docs
```

### Step 2: Login to Get Token

1. Expand **Authentication** → **POST /auth/login**
2. Click **Try it out**
3. Enter credentials:
```json
{
  "email": "admin@aicn.africa",
  "password": "Test123!@#"
}
```
4. Click **Execute**
5. Copy the `token` from response:
```json
{
  "success": true,
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
  }
}
```

### Step 3: Authorize in Swagger

1. Click **Authorize** button (🔒 lock icon, top right)
2. Paste token (without quotes)
3. Click **Authorize**
4. Click **Close**

✅ **Success Indicator**: Lock icon becomes closed 🔒

### Step 4: Verify Authentication

Test with `GET /auth/me`:
- Should return your user profile
- If you see 401, token wasn't set correctly

## Role-Based Testing

### 🔴 ADMIN Tests (Full Access)

#### 1. Dashboard Statistics
```http
GET /admin/stats
```
**Expected Response:**
```json
{
  "success": true,
  "data": {
    "learners": 150,
    "trainers": 25,
    "sessions": 45,
    "certificates": 320,
    "pendingTrainerApplications": 5
  }
}
```

#### 2. List All Users
```http
GET /admin/users?page=1&limit=10&role=TRAINER
```
**Query Parameters:**
| Parameter | Values | Description |
|-----------|--------|-------------|
| role | LEARNER, TRAINER, ADMIN | Filter by role |
| search | string | Search by name/email |
| page | 1-100 | Page number |
| limit | 1-100 | Items per page |

#### 3. Update User Role
```http
PATCH /admin/users/{userId}/role
```
**Request Body:**
```json
{
  "newRole": "TRAINER",
  "approvalMessage": "Welcome to the trainer team!",
  "isRejection": false
}
```

#### 4. Create Session
```http
POST /sessions
```
**Request Body (Online):**
```json
{
  "title": "Advanced React Workshop",
  "skillArea": "Frontend Development",
  "description": "Deep dive into React hooks",
  "date": "2024-12-20T10:00:00Z",
  "durationMins": 180,
  "locationType": "ONLINE",
  "meetingLink": "https://zoom.us/j/123456789",
  "capacity": 30
}
```

**Request Body (Physical):**
```json
{
  "title": "In-Person Python Workshop",
  "skillArea": "Programming",
  "date": "2024-12-25T09:00:00Z",
  "locationType": "PHYSICAL",
  "venue": "Nairobi CBD, Tech Hub",
  "county": "Nairobi",
  "capacity": 50
}
```

#### 5. Create Announcement
```http
POST /admin/announcements
```
**Request Body:**
```json
{
  "title": "System Maintenance",
  "body": "We will perform maintenance on Sunday at 2 AM. The system will be unavailable for 2 hours.",
  "audience": "all"
}
```

**Audience Options:**
- `all` - Everyone sees it
- `learners` - Only learners see it
- `trainers` - Only trainers see it

#### 6. Batch Issue Certificates
```http
POST /certificates/batch/{sessionId}
```
**Response:**
```json
{
  "success": true,
  "data": {
    "total": 25,
    "issued": 24,
    "failed": 1,
    "errors": [
      {
        "userId": "user123",
        "userName": "John Doe",
        "error": "Email sending failed"
      }
    ]
  }
}
```

#### 7. Approve Trainer Application
```http
PATCH /trainers/admin/applications/{applicationId}/approve
```
**Request Body:**
```json
{
  "message": "Congratulations! Your application has been approved."
}
```

## Complete Test Workflows

### Workflow 1: Complete Learner Journey

| Step | Endpoint | Action | Expected Result |
|------|----------|--------|-----------------|
| 1 | `POST /auth/login` | Login as LEARNER | Get JWT token |
| 2 | `GET /sessions` | Browse sessions | List of available sessions |
| 3 | `POST /enrolments` | Enroll in session | 201 Created |
| 4 | `GET /enrolments/me` | Check enrolment | Status: ENROLLED |
| 5 | *(Wait for session date)* | Attend session | - |
| 6 | `GET /enrolments/me` | Check attendance | Status: ATTENDED |
| 7 | `GET /certificates/me` | Get certificate | Certificate appears |
| 8 | `GET /certificates/verify/{code}` | Verify certificate | Valid certificate |

### Workflow 2: Trainer Application & Approval

| Step | Role | Endpoint | Action |
|------|------|----------|--------|
| 1 | LEARNER | `POST /trainers/apply` | Submit application |
| 2 | LEARNER | `GET /trainers/me` | Check status (PENDING) |
| 3 | ADMIN | `GET /trainers/admin/applications` | View pending applications |
| 4 | ADMIN | `GET /trainers/admin/applications/{id}` | Review application details |
| 5 | ADMIN | `PATCH /trainers/admin/applications/{id}/approve` | Approve application |
| 6 | TRAINER | `POST /auth/login` | Login as TRAINER |
| 7 | TRAINER | `GET /trainers/me` | Verify role changed |

### Workflow 3: Session Management (Admin)

| Step | Endpoint | Action | Verification |
|------|----------|--------|--------------|
| 1 | `POST /sessions` | Create session | Check response 201 |
| 2 | `GET /sessions/{id}` | View session | Verify all fields |
| 3 | `PUT /sessions/{id}` | Update session | Capacity changed |
| 4 | `GET /sessions?upcoming=true` | List sessions | New session appears |
| 5 | `DELETE /sessions/{id}` | Cancel session | Status becomes CANCELLED |

### Workflow 4: Certificate Management

| Step | Role | Endpoint | Action |
|------|------|----------|--------|
| 1 | ADMIN | `POST /sessions` | Create session |
| 2 | LEARNER | `POST /enrolments` | Enroll learner |
| 3 | TRAINER | `PATCH /enrolments/{id}/attend` | Mark attendance |
| 4 | ADMIN | `POST /certificates` | Issue single certificate |
| 5 | ADMIN | `POST /certificates/batch/{sessionId}` | Batch issue for all |
| 6 | LEARNER | `GET /certificates/me` | Verify certificate received |

## Expected Responses

### Success Responses

#### 200 OK (GET, PUT, PATCH)
```json
{
  "success": true,
  "message": "Resource retrieved/updated successfully",
  "data": { ... }
}
```

#### 201 Created (POST)
```json
{
  "success": true,
  "message": "Resource created successfully",
  "data": { ... }
}
```

#### 204 No Content (DELETE)
```json
{
  "success": true,
  "message": "Resource deleted successfully"
}
```

### Paginated Response
```json
{
  "success": true,
  "message": "Resources retrieved successfully",
  "data": [ ... ],
  "pagination": {
    "page": 1,
    "limit": 10,
    "total": 45,
    "totalPages": 5,
    "hasNextPage": true,
    "hasPrevPage": false
  }
}
```

### Error Responses

#### 400 Bad Request
```json
{
  "success": false,
  "message": "Validation failed",
  "code": "VALIDATION_ERROR",
  "errors": [
    {
      "field": "email",
      "message": "Invalid email format",
      "received": "invalid-email"
    }
  ]
}
```

#### 401 Unauthorized
```json
{
  "success": false,
  "message": "Authentication required",
  "code": "AUTHENTICATION_ERROR"
}
```

#### 403 Forbidden
```json
{
  "success": false,
  "message": "Access denied. Admin role required.",
  "code": "AUTHORIZATION_ERROR"
}
```

#### 404 Not Found
```json
{
  "success": false,
  "message": "Session not found",
  "code": "NOT_FOUND"
}
```

#### 409 Conflict
```json
{
  "success": false,
  "message": "User with email john@example.com already exists",
  "code": "CONFLICT_ERROR"
}
```

#### 500 Internal Server Error
```json
{
  "success": false,
  "message": "Internal server error",
  "code": "DATABASE_ERROR"
}
```

## Troubleshooting

### Common Issues and Solutions

| Issue | Likely Cause | Solution |
|-------|--------------|----------|
| **401 Unauthorized** | Token missing or expired | Re-login and get new token |
| **403 Forbidden** | Wrong role for endpoint | Use correct role credentials |
| **404 Not Found** | Invalid ID | Verify ID exists in system |
| **400 Bad Request** | Invalid data format | Check request body schema |
| **409 Conflict** | Duplicate resource | Use different email/session |
| **Token not persisting** | Browser issue | Re-authorize after page refresh |
| **CORS errors** | Frontend/backend mismatch | Check CORS configuration |

### Quick Debug Steps

1. **Verify server is running:**
   ```bash
   curl http://localhost:3000/api/v1/health
   ```

2. **Test authentication manually:**
   ```bash
   curl -X POST http://localhost:3000/api/v1/auth/login \
     -H "Content-Type: application/json" \
     -d '{"email":"admin@aicn.africa","password":"Test123!@#"}'
   ```

3. **Test protected endpoint:**
   ```bash
   curl -X GET http://localhost:3000/api/v1/admin/stats \
     -H "Authorization: Bearer YOUR_TOKEN_HERE"
   ```

4. **Clear Swagger cache:**
   - Hard refresh browser (Ctrl+Shift+R)
   - Clear browser cache
   - Re-authorize with fresh token

### Getting Help

1. Check auth-info endpoint: `http://localhost:3000/api-docs/auth-info`
2. View raw spec for debugging: `http://localhost:3000/swagger.json`
3. Check server logs for detailed errors
4. Verify test users exist in database

## Tips for Effective Testing

### 🎯 Best Practices

1. **Save tokens for each role** in a text file for quick switching
2. **Test sequentially** - Create data before trying to read/update it
3. **Use filters** to narrow down results and verify pagination
4. **Check edge cases** - Empty results, max limits, invalid data
5. **Verify error messages** are clear and helpful

### 📝 Test Data Management

Create test data in this order:
1. Sessions (ADMIN)
2. Enrolments (LEARNER)
3. Attendance (TRAINER)
4. Certificates (ADMIN)

### 🔄 Role Switching Quick Guide

```markdown
1. Click Authorize button
2. Click Logout
3. Login as different role
4. Copy new token
5. Authorize with new token
6. Test endpoints for that role
```

### 🚀 Performance Testing Tips

- Use pagination with small limits for faster responses
- Monitor request duration in Swagger UI
- Check for N+1 queries in list endpoints
- Verify indexes are used for filtered queries
