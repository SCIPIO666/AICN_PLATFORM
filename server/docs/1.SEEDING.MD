# Database Setup and Seeding Guide

Follow these steps to initialize the PostgreSQL database, configure your environment variables, and run the seed script on a fresh installation.

## Prerequisites

Ensure you have the following installed on your machine:
*   **PostgreSQL** (running locally or hosted remotely)
*   **Node.js** (v18+ recommended)
*   **npm** or **yarn**

---

## Step 1: Create the Database

1. Open your terminal or a PostgreSQL client (like `psql` or pgAdmin).
2. Run the following SQL command to create a new database:

```sql
CREATE DATABASE your_database_name;

```

---

## Step 2: Configure Environment Variables

1. In the root directory of the project, look for a `.env.example` file (if available), or create a new file named `.env`.
2. Add your PostgreSQL connection string to the `DATABASE_URL` variable.

The format for the connection string is:
`postgresql://USER:PASSWORD@HOST:PORT/DATABASE?schema=SCHEMA`

**Example `.env` configuration:**

```env
DATABASE_URL="postgresql://postgres:secure_password@localhost:5432/your_database_name"

```

---

## Step 3: Apply Migrations and Generate Prisma Client

Before seeding, ensure your database schema matches your Prisma schema and that the Prisma Client is generated.

```bash
# Run migrations to create tables
npx prisma migrate dev --name init

# Generate the Prisma client
npx prisma generate

```

---

## Step 4: Run the Seed Script

Execute the seed file directly using Node.js to populate your freshly created database with initial data:

```bash
node prisma/seed.js

```

If your configuration is successful, you should see confirmation logs indicating the database was populated.

## 2. How Swagger is Used to Document APIs

Swagger (OpenAPI) is used to create interactive, self-updating documentation for your REST APIs. Instead of maintaining a static PDF or Wiki page that quickly gets outdated, Swagger generates a live UI where developers can read about your endpoints and actually test them in real-time.

### How it works in a Node.js/Express environment:
1. **The Specification:** You write API definitions using OpenAPI rules (YAML or JSON). This includes details like endpoints (`/api/users`), HTTP methods (`GET`, `POST`), required parameters, and expected response codes (`200 OK`, `400 Bad Request`).
2. **The Code Integration:** You typically use packages like `swagger-jsdoc` and `swagger-ui-express`. You can write your documentation as comments (JSDoc) right above your Express route code.
3. **The User Interface:** The middleware parses those comments and spins up a visual dashboard (usually hosted at `/api-docs`).

### Quick Code Example:
```javascript
/**
 * @openapi
 * /api/health:
 *   get:
 *     summary: Check database health
 *     description: Returns the connection status of the database.
 *     responses:
 *       200:
 *         description: Database is connected and healthy.
 */
app.get('/api/health', async (req, res) => {
  // Your route logic here
});

```

## 3. Writing Your Database Connection Test

To test the specific database module you provided, you want to verify two things:

1. It successfully connects when configuration is correct.
2. It throws an error gracefully when the connection details are invalid.

We will use **Jest** for this test. Since database operations can affect state, we will mock your `logger` to keep the test console clean, and use a separate test execution block.

### `tests/db.test.js`

```javascript
const { prisma, connectDB } = require('../config/db'); // Adjust this path to where your snippet is saved
const logger = require('../utils/logger');

// Mock the logger to prevent test logs from cluttering the terminal
jest.mock('../utils/logger', () => ({
  info: jest.fn(),
  error: jest.fn(),
}));

describe('Database Connection Test', () => {
  
  // Clean up connections after tests finish
  afterAll(async () => {
    await prisma.$disconnect();
  });

  test('should successfully connect to the database', async () => {
    // Act
    const isConnected = await connectDB();

    // Assert
    expect(isConnected).toBe(true);
    expect(logger.info).toHaveBeenCalledWith('Database connected');
  });

  test('should throw an error and log failure when connection fails', async () => {
    // Arrange: Force prisma to disconnect or manipulate the client to throw
    // Alternately, you can temporarily break the adapter for this test instance
    jest.spyOn(prisma, '$connect').mockRejectedValueOnce(new Error('Connection timeout'));

    // Act & Assert
    await expect(connectDB()).rejects.toThrow('Connection timeout');
    expect(logger.error).toHaveBeenCalledWith(
      'Database connection failed:',
      'Connection timeout'
    );
  });
});

```

### To Run the Test:

1. Ensure Jest is installed: `npm install --save-dev jest`
2. Add a test script to your `package.json`:
```json
"scripts": {
  "test": "jest"
}

```


3. Run `npm test` in your terminal.
